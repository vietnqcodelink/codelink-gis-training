# GIS Training: Ho Chi Minh City map

MapLibre comparison app for Raw GeoJSON, PMTiles, MBTiles and PNG raster tiles.

The repository contains the frontend and the data-building script. It does not contain the large OSM source extract or generated map data. A fresh clone can compile the frontend, but map layers need their data files generated first.

## Quick start

Use Node.js 22 and install the GIS tools. On macOS with Homebrew:

```bash
brew install gdal osmium-tool tippecanoe jq sqlite3 node
```

Install the `pmtiles` command line binary for your OS from the [official releases](https://github.com/protomaps/go-pmtiles/releases). Check that `osmium`, `ogr2ogr`, `tippecanoe`, `tile-join`, `pmtiles`, `jq`, and Node/npm are available. To create PNG tiles, `gdal_rasterize`, `gdaldem`, and `gdal2tiles.py` are also required.

From the repository root, run:

```bash
npm ci
./scripts/build-data.sh --download
npm run dev
```

`--download` fetches the current Vietnam extract from [Geofabrik](https://download.geofabrik.de/asia/vietnam.html) into `vietnam.osm.pbf` if it is not already there. To use a PBF you downloaded yourself, put it at that path and omit `--download`:

```bash
./scripts/build-data.sh
```

The script builds the HCM boundary, roads and wards, merged Raw GeoJSON, vector MBTiles, PMTiles, then regenerates the data manifest and snapshot label. For the optional PNG mode, add `--png`:

```bash
./scripts/build-data.sh --download --png
```

The script checks for required tools and stops with a clear error if a dependency or input is missing. Its default HCM OSM relation ID is `1973756`. If that relation is missing in a later extract, find the level-4 HCM relation and rerun with its ID:

```bash
mkdir -p out/hcm
osmium tags-filter vietnam.osm.pbf r/boundary=administrative \
  -o out/hcm/admin.osm.pbf
osmium tags-filter out/hcm/admin.osm.pbf r/admin_level=4 -f osm \
  > out/hcm/admin-level4.osm
grep -n -B 15 'name" v="Thành phố Hồ Chí Minh"' \
  out/hcm/admin-level4.osm
HCM_RELATION_ID=123456 ./scripts/build-data.sh
```

Replace `123456` with the ID shown on the matching `<relation id="...">` line.

## Generated files

| Path | Purpose | Required to run |
| --- | --- | --- |
| `public/hcm.geojson` | HCM boundary for both maps | Yes |
| `public/hcm-road-wards.geojson` | Raw GeoJSON roads and wards | Yes |
| `public/hcm-road-wards.pmtiles` | Main vector-tile archive | Yes |
| `out/hcm/hcm-road-wards.mbtiles` | Intermediate archive; also used by TileServer GL | Needed to build PMTiles; server mode optional |
| `public/raster-roads/`, `public/raster-wards/` | Folder-based raster tiles | Only for PNG mode |
| `public/data-manifest.json` | OSM snapshot, sizes and SHA-256 checksums | Generated by the script |
| `src/dataSnapshot.ts` | Snapshot label shown by the app | Generated by the script |

The source PBF, `out/`, generated GeoJSON/PMTiles and PNG tiles are ignored by Git. Docker excludes the PBF and intermediate `out/` directory from its build context, while including generated files under `public/`. Run the data script before building a production image.

The Geofabrik `latest` extract changes over time, so rebuilding it later can produce different data. The manifest records the snapshot and SHA-256 of the exact PBF used. For a repeatable rebuild, use the same archived extract and verify its hash against the manifest.

## Optional: MBTiles mode

The app defaults to the production endpoint `https://gis-api.vioralabs.site/data/hcm-road-wards/{z}/{x}/{y}.pbf`. To run the generated MBTiles file locally with Docker:

```bash
docker run --rm -p 8080:8080 \
  -v "$PWD/out/hcm/hcm-road-wards.mbtiles:/data/hcm-road-wards.mbtiles:ro" \
  maptiler/tileserver-gl \
  --file /data/hcm-road-wards.mbtiles --port 8080
```

Set `VITE_MBTILES_TILE_URL` to the local endpoint when running Vite or building. Vite embeds this setting at build time, and the browser must be allowed to access the endpoint through its CORS policy:

```bash
VITE_MBTILES_TILE_URL="http://127.0.0.1:8080/data/hcm-road-wards/{z}/{x}/{y}.pbf" npm run dev
```

## Build and validate

```bash
npm run build
npm run lint
pmtiles verify public/hcm-road-wards.pmtiles
sqlite3 out/hcm/hcm-road-wards.mbtiles \
  "select zoom_level, count(*) from tiles group by zoom_level order by zoom_level;"
```

The map style, center, and default MBTiles URL are in `src/config.ts`. The production web Dockerfile and Nginx configuration are `Dockerfile` and `nginx.conf` at the repository root. Build the image from this directory and pass the source revision for the on-page build tag:

```bash
docker build \
  --build-arg APP_COMMIT_SHA="$(git rev-parse HEAD)" \
  -t gis-training-web .
```

The static app is deployed at `https://gis-training.vioralabs.site`; the production MBTiles API is `https://gis-api.vioralabs.site`.
